# Portable save format

## Status

This document specifies `CHORUS_PORTABLE_SAVE` schema version 1 and the browser
slot contract that stores the same text. It is a compatibility specification,
not an invitation for another program to invent new decisions. A valid save
must reproduce from the current authored generator and reducer.

## File form

The exported file is UTF-8 text with:

```text
CHORUS SAVE · 1
{
  "format": "CHORUS_PORTABLE_SAVE",
  "schemaVersion": 1,
  "provenance": { ... },
  "payload": { ... },
  "integrity": { ... }
}
```

The trailing newline is conventional. Import also accepts the JSON object
without the human-readable header and tolerates a UTF-8 byte-order mark. Other
prefixes are rejected.

Maximum encoded file size: 512 KiB.

## Envelope

### Top level

| Field | Type | Requirement |
|---|---|---|
| `format` | string | Exactly `CHORUS_PORTABLE_SAVE`. |
| `schemaVersion` | integer | Exactly `1` after migration. |
| `provenance` | object | Required and strictly validated. |
| `payload` | object | Contains seed and complete night state. |
| `integrity` | object | Declares deterministic corruption check. |

### Provenance

| Field | Type | Requirement |
|---|---|---|
| `app` | string | Exactly `CHORUS`. |
| `generatorVersion` | integer | Must equal the generator that reconstructs the seed. |
| `exportedAt` | string | Canonical UTC ISO timestamp ending in `Z`. |
| `exportMode` | string | Exactly `player-controlled`. |
| `storageScope` | string | Exactly `portable-text`. |
| `networkRequired` | boolean | Exactly `false`. |

### Payload

| Field | Type | Requirement |
|---|---|---|
| `seed` | integer | Inclusive range 0 through 4,294,967,295. |
| `state` | `NightState` object | Must match the seed, pass state validation, and reproduce through replay. |

### Integrity

| Field | Type | Requirement |
|---|---|---|
| `algorithm` | string | Exactly `fnv1a-32`. |
| `digest` | string | Eight lowercase hexadecimal characters. |

The digest covers canonical JSON for every top-level field except `integrity`.
Object keys are sorted recursively; array order is retained; non-finite and
unsupported values are rejected.

## Night state

The payload stores enough data to verify and restore the concurrent night:

- `seed`;
- `elapsedMinutes`, from 0 through 1,440;
- `turn`, from 0 through 24;
- exactly the six rooms generated by the seed;
- one decision event per turn;
- bounded scheduled ambient events; and
- the identifiers of processed pulses.

Each room stores its active register, entered/completed state, scene cursor,
current metrics, optional immutable completion metrics, inbound and local event
identifiers, assembled support, five fatigue channels, modeled platform
minutes, and current pressure phase where applicable.

Each accepted decision stores its source identities, label and intent, modeled
duration, relational record, optional conversation route, optional register and
pressure transitions, optional last-resort record, sparse framework moves, and
exactly six effects.

The format includes authored labels to make the file inspectable, but labels do
not authorize replay. The generated seed, source scene, and choice identifiers
are authoritative.

## Import sequence

`parsePortableSave` performs the following sequence:

1. verify input type and byte limit;
2. remove optional byte-order mark and supported header;
3. parse JSON;
4. bound the entire value tree;
5. validate or migrate the envelope;
6. validate current envelope shape;
7. verify deterministic integrity;
8. validate timestamp and seed;
9. generate the current pack for that seed;
10. require a matching generator version;
11. validate state shape and runtime invariants;
12. reconstruct every decision in order; and
13. require canonical equality between reconstructed and imported state.

Only after this sequence succeeds does the interface show a preview. Loading
still requires a second player action.

## Preview contract

Preview deliberately excludes free-form story and choice content. It contains:

- format and schema version;
- generator version;
- export time;
- seed;
- turn;
- elapsed logical minutes;
- count of entered rooms; and
- count of completed rooms.

This permits review without rendering an imported narrative or replacing the
current state.

## Migration

Schema 0 was an internal prototype with generator version, export time, seed,
state, and integrity at the top level. Migration to schema 1 follows these
rules:

1. validate the legacy field shape;
2. validate UTC timestamp and seed;
3. verify the legacy checksum before conversion;
4. place legacy values in the schema-1 provenance and payload sections; and
5. calculate a new schema-1 checksum.

The parser reports `migratedFrom: 0`. Unsupported schema versions fail with no
best-effort coercion. Migration does not bypass current generator-version or
replay validation.

## Browser slot contract

Slots A, B, and C store the complete portable text under three fixed keys. A
write or clear requires a `LocalSlotConsent` capability containing:

```text
kind: chorus-local-slot-consent
slot: A | B | C
granted: true
```

The capability is created only after the player enables that slot in the open
privacy panel. It is not serialized. Reads are also deliberate: inventory and
load functions do nothing until called.

## Error codes

| Code | Meaning |
|---|---|
| `SAVE_TOO_LARGE` | Encoded input exceeds 512 KiB. |
| `INVALID_JSON` | JSON cannot be parsed. |
| `INVALID_STRUCTURE` | Envelope, tree, field, collection, or value shape is invalid. |
| `INVALID_FORMAT` | Header or format identifier does not identify a CHORUS save. |
| `UNSUPPORTED_SCHEMA` | Schema has no explicit migration path. |
| `INTEGRITY_MISMATCH` | Content changed without a matching deterministic digest. |
| `INVALID_TIMESTAMP` | Export time is not canonical valid UTC. |
| `SEED_RANGE` | Seed is not a 32-bit unsigned integer. |
| `GENERATOR_VERSION_MISMATCH` | The current generator cannot promise the same authored pack. |
| `STATE_INVALID` | State shape, event history, timing, metrics, or replay is inconsistent. |
| `SLOT_CONSENT_REQUIRED` | A browser write or clear was attempted without selecting the slot. |
| `STORAGE_UNAVAILABLE` | Browser storage could not be read, written, or cleared. |
| `SLOT_EMPTY` | The selected slot contains no value. |

User-facing copy may be shorter than these definitions but must identify the
action that failed without exposing internal data or replacing the current
night.

## Compatibility guarantees

CHORUS guarantees that:

- schema-1 text can be inspected independently as JSON;
- an unmodified save with the matching generator version reproduces the same
  logical night state;
- ordinary field order does not change the canonical digest;
- an accepted register switch, conversation route, pressure transition,
  framework move, last resort, and six-effect receipt survive replay; and
- a rejected file cannot partially update application state.

CHORUS does not guarantee that:

- a future generator can replay a prior generator version;
- the checksum proves authorship or prevents intentional editing;
- a browser slot survives clearing browser data or switching browser profiles;
- a downloaded file is encrypted; or
- files remain available after the player deletes or moves them.

## Version-change checklist

Before changing the format:

1. decide whether the change belongs to the envelope schema, generator version,
   or both;
2. preserve preview-before-load behavior;
3. define explicit bounds for every new value;
4. add shape and replay checks before rendering;
5. add valid, corrupt, recomputed-checksum, oversized, deep, foreign, and old
   version fixtures;
6. document migration and rejection behavior;
7. verify that no migration performs storage or network I/O; and
8. update the traceability matrix and decision record.
